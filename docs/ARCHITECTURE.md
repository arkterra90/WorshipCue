# WorshipCue architecture

## Scope and ownership

WorshipCue remains a native C++17 / Qt 6 Widgets application with local SQLite storage, managed media/background assets, and saved presentation settings.

```text
MainWindow ───────── LibraryRepository ─── SQLite library
    │                       └── songs/presentations, slides, services, entries
    ├── MediaManager ─────── library-owned media files and image thumbnails
    ├── BackgroundLibraryDialog ─── reusable library-owned still backgrounds
    ├── LyricsImporter ──── text/ChordPro to editable song slides
    ├── PresentationController ─── live service snapshot with shared-text refresh
    ├── MediaPlayback ────── one Qt Multimedia decoder / shared live frame
    └── OutputManager ────── two audience and two stage DisplayWindows

WorshipCueMcp ── McpServer ── LibraryRepository ── same SQLite library

SlideRenderer ─── audience window, live/selected/next previews, slide thumbnails
BatchRenamer ─── naming rules and collision validation
```

`MainWindow` owns the repository, presentation controller, output manager, media playback, and media manager. `OutputManager` owns four top-level output windows. Windows borrow the controller; the audience also borrows the shared playback frame. Outputs do not query SQLite. Qt parent ownership manages operator widgets and connections.

## PresentationController: a stable live service

Taking a slide live copies the complete service into an in-memory snapshot: entry IDs, titles, slide text, media metadata, order, background assignments, and presentation timing/resolved transition settings. Next/Previous navigate that snapshot across entries and hold the first/last slide at service boundaries. Text lists remain present for compatibility; a media slide can have empty text and a valid image/video descriptor. An empty text string does not make that slide an empty service item.

Service switching, deletions, and reordering preserve the live snapshot. Structured song text updates use stable section/page keys to refresh its matching occurrences. Taking another slide live explicitly captures the current saved service. Media and background paths become absolute when constructing the live snapshot, while persistent references stay relative to the library directory. Upcoming previews carry the next presentation's background, including presentation-loop boundaries. A cue revision increments on deliberate takes/navigation so retaking the same video restarts it. Clear/Blackout/Restore do not change that revision.

Clear hides audience text and retains its image/video and audio. Blackout paints the audience black and temporarily mutes video audio while its playhead continues. Restore removes either state without restarting playback. Taking or advancing to a valid slide restores normal audience content. Stage retains useful lyrics, media labels, and its clock. An invalid boundary-navigation request holds both content and output state.

The controller owns a single-shot precise auto-advance timer. `PresentationSettings` supplies an interval (zero disables timing), a presentation loop flag, a transition type, and transition duration. Timer expiry advances only within the current presentation, loops to its first slide if requested, or completes after its last interval. Manual Next/Previous can still cross service items. Each successful cue resets the interval; explicit takes clear manual pause. Pausing stores remaining milliseconds. Blackout/clear also suspend timing, independently of manual pause. Timer status has its own signal, so countdown updates do not restart media or issue a slide cue. The operator polls remaining time every 100 ms.

Auto-advance and looping belong to the library presentation. Program transition defaults live in QSettings (`presentation/transitionType` and `presentation/transitionDurationMs`). `PresentationSettings::resolvedWithDefaults()` uses those defaults unless the presentation's `overrideTransition` flag is enabled. `MainWindow` resolves each item when capturing the live service; the controller resolves updated global defaults on the next inherited cue or output-state operation. Saved presentation overrides take effect on the next explicit take. The incoming item supplies the transition type/duration.

## LibraryRepository: versioned content and services

The default database is `library.sqlite3` in Qt's `QStandardPaths::AppDataLocation`. Tests can supply a path or `:memory:`. Each repository owns a unique SQL connection and removes it on close.

Schema version **9**, recorded in `PRAGMA user_version`, contains:

| Table | Purpose |
|---|---|
| `songs` | Shared title/ID, timing/transitions, background assignment, validated section/arrangement metadata |
| `slides` | Ordered text plus media kind, relative path, display name, and video loop flag |
| `services` | Named saved plans |
| `service_entries` | Independent IDs, a presentation or media-asset reference, position, optional slide order |
| `media_assets` | Independent assets, shared paths, display names, folder labels, looping, nullable import dates |

Version 0 migrates to version 1 by preserving songs, slides, service-entry IDs, and order in **My Service**. Version 1 then adds media columns; version 2 adds presentation timing/transitions with manual/Cut defaults. Version 3 adds `transition_override` and `background_path`: existing non-Cut transitions or durations other than 500 ms become explicit overrides, while the previous default inherits program settings. Version 4 adds optional rich text per slide, defaulting to empty metadata for legacy appearance. Settings and managed background paths are validated on reads and writes; create operations include them in their transaction. Each migration is transactional; a failed migration rolls back its own changes. Unknown newer schema versions are rejected. Samples are seeded only for a new library, so intentionally deleting all songs stays effective after restart.

Media presentation creation validates aligned text/media lists, valid kinds, normalized managed `media/...` references, unique media names, and video-only looping. Song text editing rejects media presentations to prevent replacing imported assets accidentally; a separate operation renames their presentation title. Media-name updates are transactional and preserve stored paths. Search includes titles, lyrics, and media names using bound parameters with literal LIKE-wildcard escaping.

Song edits, service copies, entry duplication, and ordering use transactions. Foreign keys cascade library deletion into saved service entries; removing an entry leaves its library content intact. Copies share underlying content and media. Service and entry IDs use `AUTOINCREMENT` to avoid identifying a newly inserted entry as a deleted live entry. Deleting a presentation does not currently reclaim media files, preserving files used by copies or active snapshots.

Arrangements store source-slide indices in JSON. Null/empty means natural order. Per-entry arrangements may repeat or omit slides; the UI exposes ordering and reset. Plain text, rich HTML, and media arrays follow the same indices. A legacy flat text song's slide-count change resets affected saved arrangements to natural order transactionally; same-count edits preserve them. Structured songs use stable section/page keys and named reference arrangements. Their editor preserves surviving slide IDs and remaps custom orders when section groups change.

Writes return errors; read failures are logged and exposed through `lastError()`. Callers must inspect a read error before issuing another repository operation.

## MCP service planning

`WorshipCueMcp` is a separate console executable linked to Qt Core, Network, and SQL. AI clients launch it over newline-delimited JSON-RPC on stdin/stdout; diagnostics go to stderr. The app build includes it beside the GUI executable (inside the macOS bundle). It uses the same organization/application identity and repository implementation; `--database` selects the exact library. There is no socket listener, embedded model, or model credential storage.

`McpServer` exposes library search, presentation inspection, saved service listing/inspection, standalone song/sermon text presentation creation, and new service-order creation. `PlanningCenterClient` reads Services plans over authenticated HTTPS using credentials from the process environment. It enforces the API host, rejects redirects/foreign pagination, and bounds response size and request time. Import previews resolve library matches, available lyrics, and labelled sequences; unresolved items block the atomic save unless overridden or explicitly permitted as placeholders. Ordinary item notes are not projected. Planning Center remains read-only. Schemas and runtime validation bound inputs and distinguish existing presentation references from new plain-text slides. A dry run returns an ordered preview. Committing delegates to `LibraryRepository::createServiceOrder`, which validates references and arrangements and saves the service, new presentations, slides, and entries in one SQLite transaction. It does not call individual transaction-owning repository mutations inside that transaction. Repeated entries receive separate IDs; existing library content retains its settings and media.

The GUI polls `PRAGMA data_version` on its own connection once per second. A committed change from another connection refreshes saved services and library content while preserving the operator's selected service, entry, slide, and the controller's live snapshot. Refresh waits while a modal dialog or mouse drag is active. The Settings-menu setup dialog generates client configuration from the actual executable and database paths. See [MCP setup and tool usage](MCP.md).

## MediaManager: managed imports and thumbnails

Importing copies selected files into `media/<batch UUID>/<chosen filename>` beside the database. Original files are unchanged. Stored paths are relative, allowing the closed database and its media directory to move together. A batch UUID isolates import destinations from existing content; files are never overwritten.

`MediaManager` copies in a Qt Concurrent worker, validates readable images, preserves extensions, checks names, and reports progress and cancellation. Each file uses `QSaveFile`; a failed/canceled batch cleans its directory. `MainWindow` registers standalone assets after copying and can create a batch presentation when explicitly selected. It discards the batch if database registration fails. Optional service insertion uses the service captured when the import began. Browsing another service during import does not change the destination. If adding the entry fails, the imported library item remains available and the operator receives an error.

Image thumbnails decode asynchronously and are cached. Managed-path resolution rejects paths outside the library media directory. Videos are accepted by supported container extension and validated by the playback backend when cued; extension support is not a codec guarantee. Animated image imports are treated as still images rather than motion backgrounds.

A crash between file copying and database commit can leave an unreferenced import directory. Garbage collection, import journaling, media relinking, and a complete backup/export workflow are not implemented. Backups must include the closed database and its sibling `media` and `backgrounds` directories.

## Background library and lyric import

`BackgroundLibraryDialog` scans the managed `backgrounds` directory beside the database, previews reusable still images, and copies imports with unique filenames while preserving originals. Assignment stores a normalized `backgrounds/...` path on the library presentation; an empty path selects the built-in background. Duplicating a presentation copies its assignment and shares the asset. The selected/next previews resolve their own backgrounds; the audience loads the live snapshot's assignment when the cue changes. Missing files fall back to the built-in background and appear in the operator's background status. The former global audience-background QSettings preference is no longer loaded by `MainWindow`.

`LyricsImporter` normalizes UTF-8 text, CRLF/BOM, paragraphs, explicit `---` separators, and section headings into ordinary editable song slides. It removes chord annotations and reads supported ChordPro metadata. `SongEditorDialog` offers file import and clipboard paste, validates UTF-8 files, and leaves existing editor content intact on failed imports. Imports populate the Save/Cancel editor; they do not write the repository until Save. Section headings identify slide groups and reusable sources when saved through the song import flow. The bulk review editor can rebuild those groups from edited slide breaks. Measured Reflow is available through the separate Looks / Reflow workflow.

## Batch renaming

`BatchRenamer` implements Name and Number, Replace Text, Add Text, and Keep Current Names. It preserves extensions and validates duplicate names case-insensitively with Unicode normalization. It rejects path separators, invalid Windows/macOS filename characters, reserved Windows names, trailing dots/spaces, excessive length, and invalid numbering ranges.

`MediaImportDialog` previews every current/new name before applying. Initial import uses those names for the copied physical files. Batch renaming an existing presentation changes its slide labels in SQLite while keeping physical storage paths stable; this protects live snapshots and duplicate presentations. It does not rename the user's original files or relocate managed files. The dialog explicitly distinguishes these operations.

## Operator interaction and rendering

The left sidebar switches between Content Library, Service Playlist, and Media Library tabs, each using the full sidebar height. The library identifies the current destination service; Find opens the library, and Return to Live opens the playlist. The center offers Grid thumbnails or a Text list with wrapped lyrics; a size slider adjusts thumbnails or operator text. `SlideTextDelegate` reads the existing slide roles without modifying presentation content. Thumbnails are cached at 320×180 to support the full size range. The right shows Live with audience controls immediately underneath, Up Next/Selected preview tabs, transport, and contextual timing/media controls. Column widths, sidebar tab, slide view/size, and preview tab persist in QSettings. Preview tabs retain a minimum height that fits their child preview, including during timed video playback at 1080×680.

Lyrics/media import and the background library are available from the sidebar. Presentation timing/transitions and background assignment are available in library/service context menus; global transition defaults are visible below the slide workspace and in Settings/File. Media presentation titles, labels, and arrangements persist. Picture cards show decoded thumbnails; video cards identify the filename/type. Missing media receives an operator warning.

Show mode takes a clicked slide live. Edit mode selects for preview and enables service-local reordering. Explicit Take Live remains available. Selecting another entry previews it without changing the live service. `ReorderListWidget` explicitly changes model row order for list/grid drags and saves after a complete reorder. The rich text slide editor supports direct canvas editing and per-slide undo/redo; bulk lyric import retains the Save/Cancel separator editor. Draft changes are not autosaved.

Keyboard handling excludes modal dialogs and text-entry controls. Escape returns focus to operator controls while preserving fullscreen output. The platform Find shortcut focuses the existing library search and selects its query. Return to Live in the toolbar reveals the corresponding saved service/entry through the snapshot-matching selection logic, without recapturing the snapshot, restarting playback, or restoring hidden audience content. Changed or removed saved cues receive a status message. Safety shortcuts, selected service, output routes, program transition defaults, and geometry use QSettings. See the [ProPresenter UI audit](PROPRESENTER_UI_AUDIT.md) for the comparison and verification.

`SlideRenderer` paints a fixed 1920×1080 logical canvas at each audience/preview surface. Text uses identical margins/wrapping/auto-fit. The presentation background is the base layer, using cover/crop and dimming for readable lyrics. Imported pictures and video frames sit above it, fitted without cropping or dimming; unused space reveals the background. A full-canvas JPEG covers that layer. Clear hides text while retaining background and media. Saved Looks provide shared typography, text bounds, alignment, padding, and background styling.

The audience `DisplayWindow` owns the transition compositor. Cut, Fade, Slide Left, and Slide Right combine cached outgoing/incoming canvases; a 16 ms timer updates one shared progress value. The operator live monitor paints through that same compositor, including when the audience window is hidden. Re-cueing during an animation captures its current composite as the new outgoing frame. Incoming media waits for the first decoded frame before its transition begins, retaining the outgoing visual during loading. Output clear/blackout/restore use the resolved transition hierarchy without issuing a cue. Type and duration are captured when each animation starts. Same-cue transitions start immediately, without waiting for a decoder frame. During an uninterrupted output-state transition, both canvases render the same current shared media frame, keeping video moving while lyrics fade. Interrupted transitions capture the visible composite. Stage, selected/next previews, and thumbnails remain static. No transition paint operation reads files or queries SQLite.

## MediaPlayback: one audience decoder

`MediaPlayback` owns one `QMediaPlayer`, `QAudioOutput`, and `QVideoSink`. The audience and operator live monitor draw the same decoded frame, avoiding separate decoders drifting apart. Pictures decode asynchronously; generation checks discard stale completions after rapid navigation. Playback errors and missing files are reported in the operator UI. A timeout catches video sources that produce no frames.

Video controls pause/resume, restart, and mute. An import checkbox sets looping for videos in that presentation. Non-looping videos hold their last frame unless the independent presentation timer advances the slide. Auto-advance counts from the cue, including load/transition time, and does not follow clip completion or Pause Video. Re-cueing deliberately restarts a clip. Audio uses the system output device; independent audio-device routing is not implemented. Runtime Qt Multimedia/OS codec support determines which files actually play.

## Display routing

`OutputManager` routes each output to Off, Windowed Preview, or a fullscreen screen and persists desired identities. It rejects sending audience and stage to the same fullscreen identity. A missing target stays selected as Disconnected while hidden; screen-added notifications retry it. Geometry changes refresh routing without cycling a healthy fullscreen window. Closing sets Off; Escape requests operator focus. Visibility/minimization changes update status without reopening a deliberately hidden window.

Screen identities combine OS name, manufacturer, model, and serial number. Identical identities are offered as one route. Projector identity changes, macOS Spaces, and real display reconnection need physical validation. The stage output is separate and does not play audience media/audio.

Plain text remains separately searchable and readable on Stage. `updatePresentationText` saves the title, plain text, and HTML transactionally without replacing slide IDs, media, background assignments, or source-slide arrangements. Legacy plain-text edits preserve HTML for unchanged slides and clear it where the text changes.

`SlideEditorDialog` uses a 1920×1080 graphics scene with an editable `QGraphicsTextItem`, the shared rendered background/media layer, and a thumbnail navigator. Documents retain independent undo/redo history across navigation. `RichTextSupport` canonicalizes supported text/paragraph formatting and blocks embedded resources. The same font sizes, text area, and proportional fit are used by editor and audience. A bounded cache avoids re-parsing identical HTML on every video frame. New presentation drafts allow adding/copying/removing slides; editing existing presentations preserves their structure.

The global transition bar is visible below the slide workspace, with an additional Settings-menu dialog. QSettings stores default type and duration. `setGlobalTransitionDefaults` updates the controller's pending defaults without emitting a cue or restarting timing/media. Subsequent inherited cues and Blackout/Clear Text/Restore operations resolve the latest global default; explicit presentation overrides remain fixed. Saved slide content and presentation-specific settings retain live-snapshot protection.

## Shared song sections and arrangements (Corrections 2)

Counts and IDs are bounded and validated together. The default order expands section references to canonical source indices, preserving multi-slide section boundaries and repeated occurrences. Per-entry source-index arrangements retain their override behavior.

Full section occurrences expand when pages are added. Removing a page used by a partial occurrence or removing a used section fails with a reset-order instruction. Any SQL error rolls back text, IDs, arrangements, and metadata together. Legacy grouping is created in the editor draft and persisted on Save.

`SongStructureDialog` manages unique sections, suggested/custom names, an explicit per-section slide list, slide add/duplicate/split/reorder/remove, source section reordering, repeated references, labelled previews, and named arrangement create/copy/rename/delete. Option/Alt+Return splits the selected slide at the cursor. Slide drafts retain empty pages and unchanged HTML; manual text/split edits clear only the affected page formatting. Source mappings preserve Look overrides when duplicating pages. The existing rich text canvas edits canonical source pages. Lyric imports preserve headings and page groups, share identical repeated sections, and disambiguate different lyrics using the same heading. MCP song creation uses the same import model. General text/sermon presentations retain their original flat representation.

Live items carry a song ID and stable section/page keys. `refreshSongText` updates matching lyrics and HTML throughout the service snapshot and active audience cue without issuing a cue, resetting a timer, restarting a decoder, or changing navigation order. The audience renderer rebuilds changed text on the existing cue. Structural changes are captured by an explicit take. Non-structured presentations retain snapshot editing behavior.

## Four outputs, formats, and stage layouts (Corrections 2 Priority 4)

`OutputId` identifies Audience1/Audience2/Stage1/Stage2. Legacy `Kind` routing APIs and first-pair QSettings keys remain compatible. Each `OutputConfiguration` holds its target, logical canvas, content aspect, rendering rotation, Fit/Fill/Stretch scaling, optional native signal mode, and stage-layout ID. Strict JSON validation bounds dimensions, pixels, aspect, enum values, and identifiers. Preferences live under `outputs/0..3/configuration`; definitions live under `outputs/stageLayouts`. This output feature introduced no database migration (schema 9 at that increment).

Audience1 owns the existing shared 1920×1080 transition compositor and borrowed media frame. Audience2 delegates to it and allocates no second audience compositor, transition timer, or decoder. `paintOutput` maps that shared presentation into each independently configured canvas/content aspect, rotation, and destination. Custom stage content paints in its own logical canvas with normalized element rectangles and fitted typography. The operator monitor follows Audience1; the Screens dialog offers draft previews for all four. Output reconfiguration does not issue a controller cue.

Routing rejects fullscreen collisions across all four outputs, including identities resolving to the same physical screen. Exact display identity is preferred; a unique manufacturer/model/serial identity can recover an OS-renamed screen. Ambiguous identities are hidden from assignment. Disconnects immediately hide affected windows and retain desired configuration. Geometry, refresh, and DPI changes schedule one coalesced refresh. Visibility/minimize events only update status. `shutdown` hides all outputs and releases this session’s mode leases.

`DisplayModeProvider` separates platform discovery/application from routing. Core Graphics uses the Qt Cocoa screen’s native NSScreen/display ID, enumerates usable desktop modes with the duplicate-low-resolution option so Retina/HiDPI modes and their current restoration mode are included, and applies only a matching reported mode. Qt native screen handles are version-guarded (Cocoa 6.11+, Windows 6.7+). Older supported Qt versions require a unique exact OS-name/geometry match on macOS or a matching attached Windows device name; otherwise capability reporting stays unavailable. These compatibility branches have not been runtime-tested on older Qt. See [Cocoa screen interface](https://doc.qt.io/qt-6/qnativeinterface-qcocoascreen.html) and [Windows screen interface](https://doc.qt.io/qt-6/qnativeinterface-qwindowsscreen.html). Windows uses its native HMONITOR/device name, EnumDisplaySettingsW, a CDS_TEST validation, and temporary CDS_FULLSCREEN changes without registry updates. Other platforms report desktop information and explain that physical mode switching is unavailable. Mode labels retain unknown refresh/scan information. HiDPI backing pixels, logical desktop geometry, and driver-controlled wire timing are distinguished. See [Apple display-mode enumeration](https://developer.apple.com/documentation/coregraphics/cgdisplaycopyalldisplaymodes(_:_:)), [Windows enumeration](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumdisplaysettingsw), and [Windows mode validation/application](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-changedisplaysettingsexw).

A mode lease records the previous native mode and the mode applied by this session. Mode keys include reported format properties, preventing a reused native ID from silently selecting a different format. A restorable reported current mode is required before offering native changes. Releasing a route restores the previous mode only if the screen still has the applied mode, preserving later OS/user changes. ## MIDI integration (Corrections 2 Priority 5)

`WorshipCueMidiModel` is Core-only and shared by the GUI, repository, and console companion. It validates bounded MIDI 1.0 Note On/Off and CC messages, source/channel/value wildcards, stable slide/entry/asset targets, and mutually exclusive enabled input mappings. Note On velocity zero decodes as Note Off. `MidiStreamDecoder` retains running status across packet boundaries, accepts realtime interleaving, and discards unsupported channel/system/SysEx data.

`MidiBackend` separates native transports from the engine. CoreMIDI discovers endpoint UniqueIDs, checks device offline status, connects input ports, sends to destinations, and optionally publishes virtual source/destination endpoints. WinMM discovers driver identities independent of enumeration order and opens native input/output handles. Indistinguishable identities are unavailable rather than guessed. Installed virtual/network drivers appear through these same OS interfaces. CoreMIDI is lazy so disabled MIDI does not register native clients on app launch. Platform APIs: [CoreMIDI input ports](https://developer.apple.com/documentation/coremidi/midiinputportcreate(_:_:_:_:_:)) and [Windows MIDI functions](https://learn.microsoft.com/en-us/windows/win32/multimedia/midi-functions).

Native callbacks hold a shared mutex-protected receive gate, not a raw engine pointer. The queue bounds packets to 4096 bytes and 256 pending packets. Queued GUI drains yield after at most 16 packets/8192 bytes; the engine caps processing at 256 decoded messages per packet. Overflow resets decoder/edge state and logs the loss. Input connections carry generation tokens, so queued data from a disposed/reopened port cannot trigger a new connection. QObject lifetime guards protect queued delivery. Device and stream state remain on the GUI thread.

`MidiEngine` validates and persists `midi/devices` JSON preferences (master enable, per-device enable/channel, reconnect, virtual ports, echo/debounce windows). MIDI defaults off. Discovery/reconciliation runs every second when enabled with reconnect selected; Refresh is explicit otherwise. Saved unavailable identities are retained. A failed send closes that output so reconnect can reopen it. A bounded 500-event monitor records reception, transmission, ignored edges, mappings, and native failures. Configuration and learning do not emit test output. The devices dialog retains unsaved channel/enabled drafts during automatic status updates.

Matching uses an eight-probe index over specific/wildcard source, channel, and value; enabled overlap rejection makes the result unique. Per-source note edges suppress held pads; CC values must change to rearm. Monotonic per-binding debounce and cross-source outgoing-message echo suppression bound retriggers and returned feedback. Note On/Off share an echo key; CC keys are separate and values are ignored. Master/input channel filters apply before commands. MainWindow gates control to Show mode with no modal/popup; learning and monitoring remain available. Disabling MIDI/destinations and shutdown attempt Note Off for only notes owned by WorshipCue. They never send a global All Notes Off that could silence unrelated software.

Schema 10 rebuilds legacy `songs`/`slides` with AUTOINCREMENT, preserving content, IDs, sequence high-water marks, saved Looks, and service references. It recreates slide-order/media-path indexes. Foreign keys are paused outside the transaction and restored by RAII; an integrity check must pass before commit. Actions have exactly one canonical slide, direct-media entry, or media-asset owner and ordered validated JSON. Input mappings retain relational target columns with cascading deletion plus validated JSON. Optimistic original-value guards reject stale action/mapping edits. Mapping writes validate slide membership and the nth occurrence in a target's saved order. Failed migrations/writes roll back their own changes.

`Song.slideIds` and per-source action arrays are arranged together with text/media/Looks by `MainWindow::midiSnapshot`. `PresentationController` copies them into its complete live service snapshot. Engine activation uses `cueRevision` so retakes/real navigation fire once while text refresh, Blackout/Clear/Restore, media frames, and output configuration do not. Input target dispatch rereads the saved mapping and resolves stable page IDs against fresh library/service orders; stale/removed/excluded occurrences produce monitor/status errors rather than taking another page. Select only changes browsing; takes capture fresh snapshots. New structural pages have no implicit MIDI; the surviving first reflow fragment keeps the source row and assignments. Asset defaults precede direct-media entry actions, and copied media service entries retain their own output actions.

## Library cleanup, usage, and Recovery (Corrections 2 Priority 6)

Schema 11 adds `content_usage` (one song or asset owner), `managed_files` (one relative path), `cleanup_batches`, `cleanup_files` (the permanent-removal journal), `cleanup_leases`, and `cleanup_lease_refs`. Migration is transactional and finishes with a foreign-key integrity check. Existing rows/IDs and MIDI relations remain unchanged. Legacy creation/modification/use dates are zero/unknown; existing known asset import dates are preserved. Creation/import/modification/last-use timestamps are distinct UTC seconds, displayed as local dates. Song/slide/media edits and MIDI assignment triggers update modification history; recording use never changes it. Actual lyric/media/background imports record import dates separately.

MainWindow records the currently activated source presentation, direct asset, current media path, and effective background when `cueRevision` changes. Shared asset history follows media path usage. Media preview records actual image display or an explicit audio/video Play. Selection/thumbnail browsing and future service items do not acquire false usage timestamps. New service/library snapshots publish protection before activation, combining old/new references until the transition; the active full snapshot is then renewed every ten seconds. Leases store song/asset IDs, managed paths, process ID, and a sixty-second heartbeat grace period. Expired leases remain protective while their process may be running; unknown process states err toward protection. Gracefully closed windows remove their lease. Per-operation current snapshot guards supplement persisted leases, including deleted library content retained by a live snapshot.

Candidate scans require known last use older than the custom 1–36500-day cutoff. Recent creation/import/modification/shared-file usage and physical file modification also protect content. All saved service references protect source records; presentation references protect registered media assets. Saved Looks and any active/Recovery records retain their shared files. Unknown usage, unsafe relative paths, symlinks, and unmanaged locations cannot qualify. Discovery scans only `media`/`backgrounds`, never arbitrary library/database/recovery directories, and refuses scans exceeding its 50000-item/file bound. Plans deduplicate paths and count apparent regular-file bytes only when no retained reference requires them. Database/metadata allocation, directory overhead, compression, and hard-link allocation are outside that estimate.

`LibraryCleanupDialog` provides period entry, eligibility/reason/date columns, individual/eligible-all selection, estimates, a separate record/file preview, and explicit confirmation. Find runs through QtConcurrent with an independently created/destroyed repository/SQL connection on the worker thread; GUI selections use cached candidate estimates, while operations revalidate fresh data. Closing waits for the bounded current scan to release its connection. SQLite WAL with FULL synchronous commits permits background reads alongside live usage writes and makes journal authorization durable before filesystem work. Live timers continue during scans and modal reviews. UI drafts/cancellations never mutate cleanup state.

Archive is logical: `archived_batch` hides content from public library reads while preserving every relational row, source ID, appearance, and MIDI assignment. SQL guards prevent stale writes/deletions and adding archived items to services. No files move and no disk space is reclaimed at this step. Restore clears the batch references, preserving original identities. Multiple snapshots, other Recovery records, saved Looks, and the Media Library can retain files after selected presentation records are permanently removed. This intentionally favors shared-reference safety; a subsequent scan can offer newly unreferenced assets.

Permanent removal requires a fresh reviewed plan. An IMMEDIATE transaction revalidates it and commits a `purging` batch with exact path/size/mtime journal rows. A second IMMEDIATE transaction rechecks references, leases, and post-archive file usage, then stages only removable regular files into `.cleanup-recovery/<batch UUID>/<path hash>.bin`. It deletes the selected source rows (cascading their MIDI data), clears file archive markers, and commits `purged`. Only afterward are those journaled staging files unlinked. Shared/protected files are retained. A failed transaction restores staged originals; a reopened library rolls back any uncommitted `purging` journal and completes only previously confirmed committed purges. Existing/conflicting destinations, symlinks, or changed staging files are never overwritten or followed. Unlink failures preserve journal rows for Retry. No recovery operation recursively removes a directory or unrelated files. Reusing/changing content after archiving blocks permanent removal and requires Restore plus a fresh age scan.
